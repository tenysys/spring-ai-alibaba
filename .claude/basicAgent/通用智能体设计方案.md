## 1. 实现目标

需求满足：

- 可创建、编辑、查询、发布智能体
- 可保存草稿态与发布态配置
- 可调试运行与正式运行
- 可装载模型、提示词、知识、记忆、工具、组件、SKILL
- 可进行多轮对话、工具调用、流式输出
- 可记录运行日志、工具日志、监测指标

能力结构：

```text
智能体应用层
  -> 智能体定义、版本、发布、调试

智能体运行时层
  -> AgentRequest / AgentResponse / AgentContext
  -> Prompt组装
  -> 记忆装配
  -> 知识增强
  -> Tool Calling
  -> 流式 / 非流式执行

能力适配层
  -> 模型适配
  -> Dify知识适配
  -> 数据源工具适配
  -> MCP工具适配
  -> 组件工具适配
  -> SKILL上下文适配
  -> 长期记忆适配

底层能力层
  -> common / framework / capability-component
```

## 2. 设计原则

### 2.1 总体原则

- 旧接口兼容：`common`、`framework`、`capability-component` 现有对外接口保持兼容
- 新增优先：问答/通用智能体能力通过 `basic-agent` 模块承载
- 分层清晰：应用层逻辑、运行时逻辑、能力接入逻辑与底层能力逻辑分离
- 配置收敛：调试态和发布态最终都收敛到统一的 `AgentConfig` 运行时视图
- 资源统一：业务资源和配置资源统一纳入智能体装载体系
- 可治理：日志、过滤、监测、回溯能力纳入首轮设计

### 2.2 模块定位

建议模块职责如下：

```text
basic-agent
  -> 问答/通用智能体应用层
  -> 问答/通用智能体运行时层
  -> 智能体资源装载层
  -> 智能体治理层

common
  -> 模型工厂、通用工具类、基础DTO

framework
  -> Spring配置、线程池、AOP、基础属性配置、运行时基础设施

capability-component
  -> Dify知识能力
  -> 数据源与SQL能力
  -> MCP能力
  -> 向量与检索能力
  -> 资源绑定与资源注册能力
```

## 3. 功能实现方案

## 3.1 智能体应用管理

### 功能说明

问答/通用智能体首先是一个应用，需要支持：

- 创建
- 编辑
- 复制
- 查询详情
- 查询列表
- 删除
- 调试运行
- 发布（支持发布、发布为工具、发布为应用，当前仅实现发布和发布为工具，运行态执行的最新版本）
    - 发布：支持接口调用和在运行界面使用，默认是用最新的发布版本
    - 发部为工具：作为组件被其他agent或者workflow调用，指定版本按照版本调用、不指定默认按照最新版本
    - 发部为应用：支持接口调用和运行界面使用（根据指定版本进行切换）
- 保存版本（更新草稿）
- 查看版本
- 回滚式重发版（切换历史版本，基于历史版本创建草稿）

应用状态：
DELETED 表示已删除。
对 application：这个应用已经被逻辑删除
对 application_version：这个版本记录已经被逻辑删除
一般不再参与正常查询和使用
DRAFT 表示草稿态，尚未发布。
对 application：这个应用从未正式发布过，当前还在编辑中
对 application_version：这是一条草稿版本
典型场景：新建应用后第一次保存，还没点发布
PUBLISHED 表示已发布。
对 application：当前应用最新生效内容就是已发布内容
对 application_version：这条版本是一个已发布版本
典型场景：刚发布完成，latestVersion 和 publishedVersion 指向同一条版本
PUBLISHED_EDITING 表示已发布后又被修改，当前有未发布的新内容。
对 application：线上已有发布版，但最新编辑内容还没再次发布
对 application_version：通常不会作为“版本记录的最终业务语义重点”，更多是应用整体状态在用它
典型场景：
application.status = PUBLISHED_EDITING
旧线上版本 publishedVersion.status = PUBLISHED
新编辑版本 latestVersion.status = DRAFT

### 建议服务

- `AgentAppService`
- `AgentAppVersionService`
- `AgentPublishService`
- `AgentDebugService`

### 实现要求

- 智能体主信息与运行配置分离
- 编辑态不直接影响线上发布态
- 发布态形成稳定快照，供正式运行使用

## 3.2 智能体版本管理

### 功能说明

建议采用“应用主表 + 版本快照表”模式：

- 创建应用时生成初始草稿版本
- 未发布前仅更新当前草稿版本
- 已发布后继续编辑时，基于发布版复制新草稿
- 发布时将草稿版本更新为发布版本，生成新的版本号
- 正式运行固定读取发布版本（当前固定读取最新版本）
- 调试运行读取最新版本版本（草稿/发布）

### 实现要求

- 配置快照应包含配置资源和业务资源的装载结果
- 发布后的运行配置不得依赖零散表实时拼装
- 版本必须支持回溯和审计

## 3.3 智能体运行协议

### 功能说明

建议统一运行协议：

- `AgentRequest`
- `AgentResponse`
- `AgentContext`
- `ChatMessage`
- `ToolCall`
- `Usage`

支持能力：

- 单轮问答
- 多轮对话
- 多模态输入（文本、图文和多模态，目前仅支持文本）
- 流式输出
- 非流式输出
- tool call 中间态输出（智能体工具调用显示输出，待定）

### 实现要求

- Agent 层协议独立设计
- 底层服务继续保持原有 DTO 和返回结构
- 通过适配层把底层结果转换为统一 Agent 运行协议

## 3.4 智能体配置模型

### 顶层配置对象

建议统一配置对象命名为：

- `AgentConfig`

建议包含：

- `modelProvider` 模型供应商（apikey、basrurl）
- `model` 模型名
- `modalityType` 模型类型（文本、图文、多模态）
- `instructions` 系统提示词
- `parameter` 模型参数
- `memory` 记忆
- `promptVariables` 提示词变量
- `knowledge` 知识库
- `tools` 插件（http接口）
- `mcpServers` mcp服务
- `agentComponents` 智能体组件
- `workflowComponents` 工作流组件（待定）
- `skills` skill
- `filters` 规则过滤
- `fallbackReply` 数据过滤
- `prologue` 开场白

### 配置收敛原则

```text
调试态
  -> 通过资源绑定 + 配置资源组装为 AgentConfig

发布态
  -> 将装载结果固化为快照 AgentConfig

运行态
  -> 调试运行和发布运行都统一消费 AgentConfig
 
资源绑定只能针对最新配置（草稿/发布），以前的版本仅通过配置快照，后期是否添加基于版本引用表（用于统计工具、知识库等使用）
```

## 3.7 短期记忆

### 功能说明

短期记忆用于维持多轮会话连续性。

### 实现要求

- 会话 key 建议为 `agentId + "_" + conversationId`
- 按轮数精确裁剪历史消息

### 建议新增

- `AgentChatMemoryService`
- `ConversationChatMemory`
- `MessageChatMemoryAdvisor`

- Redis 基础设施
- Spring 配置

## 8. 最终结论

`data-agent-service` 在已有模型、向量、数据源、Dify、MCP、资源绑定能力基础上，可以直接建设一套问答/通用智能体能力。

正确的落地方向是：

```text
在 basic-agent 模块中新增问答/通用智能体应用层与运行时层
  -> 用 AgentConfig + AgentVersion + Executor 建立问答/通用智能体框架

在能力接入层对接 common / framework / capability-component
  -> 模型、知识、数据源、MCP、向量、资源管理能力统一适配接入

在治理层补齐日志、过滤、监测、长期记忆等平台能力
  -> 形成可调试、可发布、可运行、可治理的问答/通用智能体体系
```

具体编码时：

- 智能体执行链、配置结构、运行协议参考 `spring-ai-alibaba-admin` 的 `BasicAgent` 设计
- 底层能力接入与资源绑定实现参考 `data-agent-service` 的 `common`、`framework`、`capability-component`
